# Read-only drill-down routes for the Standards catalog

Adds hierarchical detail routes under the Standards catalog so a user can drill from the flat tabbed index into each entity: product → versions → version assets/compatibilities; terminology release → codelists → terms; template → versions. The change introduces a shared presentational `DetailHeader` card and a flat-param routing convention (`src/routes/_app/standards/<kind>/$<id>.tsx`, each keyed on the entity's own id), and wires `onRowClick` into all three index tabs. All data is read-only through existing Orval query hooks; no mutations, no new dependencies, no edits to generated client code.

The `error` prop plumbed into `ResourceTable`/`ErrorState` is typed `AxiosError | null` while the hooks produce Orval's `ErrorType` — this already compiles clean under strict mode (confirmed by the build), so it is an accepted existing pattern, not a new gap.

**Verdict**: APPROVED

## High-level view

The drill-down is built entirely on read query hooks and the existing `ResourceTable`, which already applies `cursor-pointer`/hover affordance and renders loading/error/empty states when it receives `isLoading`/`isError`/`error`. Every detail route follows one header pattern — `isError` → `ErrorState`, `isLoading` → skeleton grid, else `DetailHeader` — so loading, error (including the 401 message), and empty states are covered uniformly across all five routes.

Routing uses one flat param per entity id rather than nested composite params, so a version/codelist route doesn't need its parent id in the URL; parent id for the back-link is recovered from the loaded record (`version.product_id`, `codelist.release_id`) with a safe `/standards` fallback while the record is still loading. Navigation targets are typed route strings, so the three index tabs and child tables are type-checked against the generated route tree.

Nullable alias fields are handled consistently: `?? '—'` for nullable strings, `formatDate` for nullable dates, `.join(', ') || '—'` for string arrays. Opaque object fields (`provenance`, `evidence`, `compatibility`, `blank_structure`) are deliberately never rendered as columns. The only generated file in the diff is `routeTree.gen.ts`, which is the router plugin's build output (standard `.update({...} as any)` form and route-tree type maps), not a hand edit; `src/api/generated/**` is untouched.

### DetailHeader as the shared presentational seam

`src/components/data/detail-header.tsx` is a pure `Card`/`CardContent` definition list taking `{ fields: { label; value: React.ReactNode }[] }`, with no data fetching. Using `React.ReactNode` for `value` is what lets callers drop a `StatusBadge`, a `formatDate` string, or a joined array into the same grid without a union type per field. Every detail route composes its own field list and owns its own data fetching, which keeps the component free of entity-specific knowledge and is the reason FEAT-002's three routes reused it unchanged.

### Flat-param routing and back-link recovery

Each detail route is keyed on a single own-id param (`$standardId`, `$versionId`, `$releaseId`, `$codelistId`, `$templateId`) rather than a nested parent/child param pair. The consequence is that a child route doesn't carry its parent's id in the URL, so the "back to parent" link has to recover the parent id from the loaded record. Both `versions/$versionId` and `codelists/$codelistId` handle this by rendering the parent link only once the record is present (`version.product_id`, `codelist.release_id`) and falling back to a plain `/standards` link while loading or on error — so the back control is always valid and never dereferences an undefined parent id.

### Uniform state handling across routes

The header block in all five routes is the same three-way branch: `isError` → `ErrorState` (which surfaces the standard 401 "Not authenticated" message for `error?.response?.status === 401`), `isLoading` → a skeleton grid sized to the field count, else `DetailHeader`. Rows are made navigable only where a child exists (products/releases index, release→codelists); terms are left as leaf rows with no `onRowClick`, which keeps the navigable-vs-leaf distinction aligned with the hierarchy.
