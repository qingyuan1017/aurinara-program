## Root cause of the regen blocker (PRE-EXISTING, OUT OF SCOPE)

`npm run api:sync` = `api:export` (boots FastAPI → writes `frontend/openapi.json`) then `orval`.
Export succeeds; **orval fails** with:

```
Duplicate schema names detected:
  2x ExportSpecificationParams, 2x ValidatePlan200, 2x PreviewPlan200,
  2x GetLineage200, 2x RenderDefineParams, 2x RenderDefineVersion
```

Cause: the committed `frontend/openapi.json` and `frontend/src/api/generated` are **pre-existing out
of sync** with the backend. The working tree carries large uncommitted backend work (the entire
ADaM module, SDTM/ADaM Define, etc.) whose OpenAPI emits the duplicate schema/operation names above,
which orval rejects. Because orval runs with `clean: true`, the failed run also deleted the whole
500-file generated tree (restored from git).

**This orval duplicate-schema blocker is pre-existing and OUT OF SCOPE for this task.** It needs a
separate fix (uniquify the colliding schema/operation names in the ADaM/SDTM-Define backend code)
before the client can be regenerated normally. Recorded here and in `verification.md` so the next
real regen reconciles cleanly against the hand-added artifacts.
