# Implementation Plan: Bulk upload of raw datasets

Source of truth: `.agents/tasks/raw-bulk-upload/design.md` (revision 3, APPROVED). Do all work
inside the worktree `e:\Work\EDETEK\Python\aurinara\.worktrees\raw-bulk-upload` on branch
`raw-bulk-upload` (based on `master`). Read source there; never use relative paths that resolve
to the parent workspace.

Real project commands (from `pyproject.toml` + `docs/local-development.md`), narrowest first:

- Lint/format: `ruff check .` and `ruff format --check .`
- Types: `mypy src workers`
- Fast tests: `pytest tests/unit tests/contract`
- Service-backed tests (need Compose Postgres+MinIO and `AURINARA_INTEGRATION=1`):
  `pytest tests/integration`
- Migration from empty DB: against a fresh `clinical_test`, `uv run alembic upgrade head` then
  `uv run alembic downgrade -1` then `uv run alembic upgrade head`.
- Frontend typed client: in `frontend/`, `npm run api:sync` (exports OpenAPI from the FastAPI app,
  then runs orval into `src/api/generated`), then `npm run typecheck`.

Prefix integration runs that use the ASGI client/`_process_job` with `AURINARA_INTEGRATION=1`; the
Phase 3 suite skips otherwise. Integration fixtures reuse `MemoryStorage`/`TestTokenVerifier` from
`tests/integration/test_phase1_core.py` and `make_test_settings()` from `tests/conftest.py`.

Design decisions are already fixed by the approved design; this plan sequences them. Where the
design named a path that does not exist, the plan uses what the repo actually has: the frontend
client is generated by orval from `frontend/openapi.json` via `npm run api:sync` (there is no
hand-written fixture to edit); the backend typed-client fixture is
`tests/contract/typed_client_fixture.py` (`PHASE3_RAW_SDTM_OPERATIONS`), asserted by
`tests/contract/test_phase3.py`.
